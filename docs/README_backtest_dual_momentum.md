# `backtest_dual_momentum.py` 使用说明

## 功能

这是一个股票池日频轮动策略：

- 用每只股票最近一段时间的涨幅做相对动量排序
- 只持有动量为正的标的，动量为负时留在现金
- 当日成交量明显高于最近均量时，会给该标的的动量分数额外加分
- 默认只持有最强的 `1` 只股票

这类做法对应文献里常见的 relative momentum + absolute momentum，也就是常说的 dual momentum。

## 直观例子

下面 3 个例子共用同一组股票池数据。为了让逻辑更清楚，我们先固定“池内谁强谁弱”，再分别看：

- 只看选股时会选谁
- 加上市场过滤后会不会空仓
- 如果允许持有多只，仓位会怎么分

统一假设如下：

- 股票池：`US.MSFT`、`US.NVDA`、`US.AAPL`
- 动量参数：短周期 `90` 日，长周期 `180` 日，长周期权重 `0.25`
- 所以短周期权重是 `0.75`
- 先忽略成交量加分，假设 3 只股票当天都没有额外 volume boost

这一天 3 只股票的动量数据是：

- `US.MSFT`：近 `90` 日涨 `20%`，近 `180` 日涨 `10%`
- `US.NVDA`：近 `90` 日涨 `18%`，近 `180` 日涨 `14%`
- `US.AAPL`：近 `90` 日跌 `-5%`，近 `180` 日跌 `-2%`

按策略里的混合公式：

- `blended_momentum = short * 0.75 + long * 0.25`

可以得到：

- `MSFT = 20% * 0.75 + 10% * 0.25 = 17.5%`
- `NVDA = 18% * 0.75 + 14% * 0.25 = 17.0%`
- `AAPL = -5% * 0.75 + -2% * 0.25 = -4.25%`

所以这一天池内强弱顺序已经确定为：

- `MSFT` 第一
- `NVDA` 第二
- `AAPL` 因为动量为负，直接失去资格

### 例子 1：先只看选股，会选谁

先只看“谁有资格入选”，暂时不看市场过滤和仓位缩放。

如果参数是：

- `top_n=1`

那么结果就是：

- 正动量候选只有 `MSFT` 和 `NVDA`
- `MSFT` 分数最高，排第一
- 所以 `candidate_codes = (MSFT,)`

这一步可以理解成：

- 策略先在池内找“最强的正动量股票”
- 当前答案是 `MSFT`

如果你原来持有的是 `AAPL`，那它也会被踢掉，因为它已经不是正动量。

### 例子 2：沿用同一组候选结果，但市场过滤没通过

现在继续沿用上面同一天的候选结果：

- `candidate_codes = (MSFT,)`

再补上市场过滤数据。这里把 `pool_ma` 的计算也写开。假设：

- `market_filter_window = 3`
- 第 1 天池内 3 只股票收盘价分别是 `MSFT=110`、`NVDA=210`、`AAPL=310`
- 第 2 天池内 3 只股票收盘价分别是 `MSFT=105`、`NVDA=205`、`AAPL=305`
- 第 3 天池内 3 只股票收盘价分别是 `MSFT=100`、`NVDA=200`、`AAPL=300`

先算每天的股票池平均价格 `pool_close`：

- 第 1 天 `pool_close = (110 + 210 + 310) / 3 = 210`
- 第 2 天 `pool_close = (105 + 205 + 305) / 3 = 205`
- 第 3 天 `pool_close = (100 + 200 + 300) / 3 = 200`

那么当天：

- `pool_close = 200`
- `pool_ma = (210 + 205 + 200) / 3 = 205`

因为：

- `200 < 205`

所以策略判定：

- `market_is_risk_on = false`

最终结果就不是买入 `MSFT`，而是：

- `target_codes = ()`
- 组合保持 `CASH`

这一步的意思是：

- 池内最强股确实已经找到了
- 但市场整体环境不允许冒险
- 所以宁可空仓，也不强行买入

### 例子 3：沿用同一组股票强弱，如果市场过滤通过，再看仓位怎么分

还是沿用同一组股票强弱：

- 第一名 `MSFT`
- 第二名 `NVDA`
- `AAPL` 淘汰

这次只改两个条件，用来说明“仓位怎么定”：

- 参数改成 `top_n=2`
- 假设这次市场过滤通过，也就是 `market_is_risk_on = true`

为了和上一个例子口径一致，也把市场过滤写开。假设：

- `market_filter_window = 3`
- 第 1 天池内 3 只股票收盘价分别是 `MSFT=90`、`NVDA=190`、`AAPL=290`
- 第 2 天池内 3 只股票收盘价分别是 `MSFT=95`、`NVDA=195`、`AAPL=295`
- 第 3 天池内 3 只股票收盘价分别是 `MSFT=100`、`NVDA=200`、`AAPL=300`

先算每天的股票池平均价格 `pool_close`：

- 第 1 天 `pool_close = (90 + 190 + 290) / 3 = 190`
- 第 2 天 `pool_close = (95 + 195 + 295) / 3 = 195`
- 第 3 天 `pool_close = (100 + 200 + 300) / 3 = 200`

那么当天：

- `pool_close = 200`
- `pool_ma = (190 + 195 + 200) / 3 = 195`

因为：

- `200 >= 195`

所以这一次：

- `market_is_risk_on = true`

再假设：

- `target_annual_vol=0.30`
- `max_gross_exposure=1.0`
- 股票池最近实现年化波动率约为 `0.60`

那么波动率缩放系数约为：

- `0.30 / 0.60 = 0.50`

这时：

- 前两名正动量股票是 `MSFT` 和 `NVDA`
- 市场允许持仓
- 但策略会把总仓位压到 `50%`

最终组合是：

- 总仓位 `gross_exposure = 0.50`
- `MSFT` 权重 `25%`
- `NVDA` 权重 `25%`
- 剩余 `50%` 现金

所以这一步说明的是：

- dual momentum 不只是决定“买谁”
- 还会决定“买几只”和“总共上多大仓位”

### 例子 4：放量只会加分，不会单独把弱票抬成强票

假设：

- `MSFT` 基础动量分数 `17.5%`
- `NVDA` 基础动量分数 `17.0%`
- `NVDA` 当日相对成交量 `1.4`
- `min_volume_ratio=1.3`

这时 `NVDA` 会得到一个放量加分，大致变成：

- `17.0% * (1.4 / 1.3) ≈ 18.3%`

于是排序可能从 `MSFT > NVDA` 变成 `NVDA > MSFT`。

但要注意：

- 放量只是给已有正动量的标的加分
- 它不是硬过滤条件
- 也不会让一个负动量标的变成可买标的

## 脚本位置

`backtest/backtest_dual_momentum.py`

## 基本用法

```bash
./.venv/bin/python -m backtest.backtest_dual_momentum \
  --codes US.MSFT US.NVDA US.GOOG US.TSLA US.AMZN US.AAPL US.V US.VOO \
  --market US \
  --initial-cash 100000 \
  --eval-start 2025-03-07 \
  --eval-end 2026-03-06 \
  --fee-account futu_alt
```

默认会从 `kline_day/<code>/` 读取按自然周拆分的日线 CSV。

## 常用参数

- `--codes`：股票池代码列表（必填）
- `--data-root`：数据根目录，默认 `kline_day`
- `--market`：必传，指定 `HK` 或 `US`；backtest 不会再从代码或目录名自动推断 market
- `--initial-cash`：初始资金，默认 `100000`
- `--lookback-days`：短周期动量回看窗口，默认 `90`
- `--long-lookback-days`：长周期动量回看窗口，默认 `180`
- `--long-lookback-weight`：长周期动量权重，默认 `0.25`
- `--top-n`：同时持有的最强标的数量，默认 `1`
- `--volume-window`：成交量比较窗口，默认 `20`
- `--min-volume-ratio`：放量加分阈值，默认 `1.3`
- `--market-filter-window`：市场风险开关均线窗口，默认 `120`
- `--rebalance-band-pct`：调仓带宽阈值，默认 `0.10`
- `--volatility-window`：波动率估计窗口，默认 `20`
- `--target-annual-vol`：组合年化波动率目标，默认 `0.30`
- `--max-gross-exposure`：最大总仓位倍率上限，默认 `1.0`（不使用杠杆）
- `--eval-start`：评估起点日期（可选），不传则按全样本统计
- `--eval-end`：评估终点日期（可选），不传则按全样本统计
- `--fee-account`：可选费用账户（如 `futu_alt`）
- `--security-type`：费用规则对应证券类型，默认 `stock`
- `--show-trades`：`1` 打印所有交易记录；`0`（默认）不打印交易记录

> 说明：当 `--max-gross-exposure > 1.0` 时，脚本会在“波动率目标缩放后的名义仓位上限”内进行受控放大，并在每笔买入前按当前仓位实时校验剩余可用名义仓位，避免超出上限。

## `market_filter_window` 怎么计算

这个参数本身不是一个“算出来的指标值”，而是一个整数窗口长度，用来做市场风险过滤均线。

策略里的计算顺序是：

1. 先取股票池当天的“平均收盘价”：

   - `pool_close[t] = mean(close_1[t], close_2[t], ..., close_n[t])`

   这里是直接对股票池里所有标的当天收盘价做算术平均。

   注意：

   - 这不是外部指数
   - 也不是先把每只股票归一化到同一起点后再做等权指数
   - 它就是代码里的 `prices.mean(axis=1)`

2. 再对这个 `pool_close` 做 `market_filter_window` 日滚动均线：

   - `pool_ma[t] = mean(pool_close[t - window + 1], ..., pool_close[t])`

   如果 `market_filter_window = 120`，那就是：

   - 先算最近 `120` 个交易日每天的股票池平均收盘价
   - 再把这 `120` 个值取平均，得到当天的市场过滤均线 `pool_ma`

3. 最后用当天 `pool_close` 和当天 `pool_ma` 比较：

   - `pool_close[t] >= pool_ma[t]` -> `market_is_risk_on = true`
   - `pool_close[t] < pool_ma[t]` -> `market_is_risk_on = false`

也就是说：

- 均线之上，才允许从正动量标的里选股票
- 均线之下，就算个股动量很好，也会先空仓

### 一个具体例子

假设股票池里有 3 只股票，某一天收盘价分别是：

- `A = 100`
- `B = 200`
- `C = 300`

那么当天：

- `pool_close = (100 + 200 + 300) / 3 = 200`

如果 `market_filter_window = 3`，并且最近 3 天的 `pool_close` 分别是：

- 第 1 天：`190`
- 第 2 天：`195`
- 第 3 天：`200`

那么第 3 天的市场过滤均线就是：

- `pool_ma = (190 + 195 + 200) / 3 = 195`

因为：

- `200 >= 195`

所以这一天：

- `market_is_risk_on = true`

如果最近 3 天的 `pool_close` 变成：

- `210`
- `205`
- `200`

那么：

- `pool_ma = (210 + 205 + 200) / 3 = 205`

因为：

- `200 < 205`

所以这一天：

- `market_is_risk_on = false`

### 两个实现细节

- 滚动均线默认包含“当天”这一根，所以比较的是“今天的股票池平均收盘价”和“包含今天在内的最近 N 天平均值”。
- 代码里要求 `min_periods = market_filter_window`，所以在前 `market_filter_window - 1` 个交易日，`pool_ma` 还不会生成有效值。

不过整套 dual momentum 策略真正开始出信号，还要同时满足别的窗口长度要求，例如：

- `lookback_days + 1`
- `long_lookback_days + 1`
- `market_filter_window`
- `volatility_window + 1`
- `volume_window + 1`

实际执行时，会取这些值里的最大值作为 warm-up 门槛。
